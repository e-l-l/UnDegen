## What this is

The entire Undegen app. There is no other frontend. React + TypeScript + Vite, Tailwind v4 (via `@tailwindcss/vite`, not a PostCSS config), shipped as an offline-first PWA.

Import alias: **`@/` → `src/`** (set in `vite.config.ts` + `tsconfig.app.json`/`tsconfig.json`). Prefer it for cross-dir imports.

## Commands

- `npm run dev` — Vite dev server. Note: PWA `devOptions.enabled = false`, so the **service worker does not run in dev**. Test SW / offline / install behaviour against a build.
- `npm run build` — `tsc -b && vite build`. Typecheck is part of the build; a type error fails the build.
- `npm test` — Node's built-in test runner with TypeScript stripping; current tests cover the day-access policy.
- `npm run preview` — serve the build (use this to exercise the SW).
- `npm run lint` — ESLint.

Package manager is **npm**. Do not introduce pnpm/yarn lockfiles.

## Design system — `src/index.css`

Tailwind v4 `@theme`. **Grayscale + a single pastel-pink accent**, app is always dark (tokens on `:root`, no light mode). Hard rule from the design: **pink is a signal, not decoration** — sanctioned uses are the primary CTA, the brand mark, progress-fill, and (as of the active-session card) a **live/active-session indicator** (icon stroke, live pill, ambient glow, ping ring — see `ActiveSessionCard.tsx` below). Never tint inputs, secondary buttons, links, or hovers pink outside those cases (a faint pink *focus ring* is the one other sanctioned exception).

Custom looping/decorative animations (breathing shadow, ping, pulse, shimmer) are defined as `--animate-*` tokens + nested `@keyframes` in a plain `@theme { }` block in `src/index.css` (Tailwind v4's native pattern — no animation library needed). Apply them via the `motion-safe:` variant at the call site so `prefers-reduced-motion: reduce` disables the loop for free (layout/colors stay, only the animation utility doesn't apply) — no JS media-query branching required.

- shadcn semantic tokens (`--background`, `--foreground`, `--primary` = the pink, `--border`, `--input`, `--ring`, …) carry the hex values above, so shadcn components inherit the look.
- Plus a named Undegen scale exposed as utilities: `bg-surface`/`bg-surface-raised`/`bg-panel`, `text-ink`/`text-ink-soft`/`text-ink-body`/`text-ink-muted`/`text-ink-dim`/`text-ink-faint`, `text-pink`/`bg-pink`/`hover:bg-pink-hover`, `border-edge-chip`/`border-edge-panel`/`border-hairline`. Plus two card-specific palettes, each dedicated rather than reusing the generic scale above (so a card's own redesign can't accidentally ripple elsewhere): `session-*` (bg/border/icon-bg/track/timer/title/muted) for `ActiveSessionCard.tsx`, and `idle-*` (bg/border/icon-bg/icon-border/title/label/track/caption/caption-strong) for `IdleGoalCard.tsx`/`IdleZenCard.tsx`.
- Font: **Inter**, bundled via `@fontsource-variable/inter` (imported in `main.tsx`) — **not** a CDN, because offline is a core feature.

## UI primitives — `src/components/ui/` (shadcn)

shadcn "new-york", set up manually (deterministic; `components.json` keeps `npx shadcn add <x>` working). `button.tsx` (cva; `default` = the pink CTA + glow, `outline` = grayscale secondary), `input.tsx` (base = mobile sizing; desktop tweaks applied at call site), `label.tsx`. `cn()` lives in `src/lib/utils.ts`.

Also `dialog.tsx` (wraps `@radix-ui/react-dialog`; deliberately unopinionated on sizing/position — that's a call-site concern, since the create-activity flow uses the same Dialog for a full-screen mobile sheet and a centered desktop card, which differ too much to bake into the primitive), `toggle-group.tsx` (wraps `@radix-ui/react-toggle-group`; bakes in the **grayscale-only selected state** — `bg-elevated`/`lg:bg-elevated-lg`, never pink — since every segmented control/weekday-cell/chip in the app is one of these), `popover.tsx` (wraps `@radix-ui/react-popover`), `calendar.tsx` (wraps `react-day-picker`'s `DayPicker`, same grayscale-selection rule), `scroll-area.tsx` (wraps `@radix-ui/react-scroll-area`; used for reliable custom-scrollbar lists, e.g. `TimePicker`'s quick-pick list — plain `overflow-y-auto` divs are fine elsewhere but this one needed a real scrollbar affordance). The `--elevated`/`--elevated-lg` tokens (`#2a2a2a`/`#303030`) live in `src/index.css` — the named "selected/elevated fill" signal, distinct from `--surface`/`--surface-raised` (which are input backgrounds, not selection states).

**`dialog.tsx` + `popover.tsx` — nested-scroll fix:** Radix Dialog's modal scroll-lock (`react-remove-scroll`) only exempts wheel/touch scroll for DOM descendants of `Dialog.Content`; anything portaled straight to `document.body` (a Popover/Select's default) is a DOM *sibling*, so the lock swallows wheel/touch scroll over it — only a scrollbar-thumb drag still works, since that sets `scrollTop` via JS rather than firing a native wheel/touchmove event. Fix: `dialog.tsx`'s `DialogContent` renders a `display:contents` div inside its own subtree and exposes it via `useDialogPortalContainer()`; `popover.tsx`'s `PopoverContent` reads that context and passes it as `Popover.Portal`'s `container` when present (falls back to `document.body` outside a Dialog). This makes any Popover-in-Dialog scroll correctly app-wide, not just `TimePicker`'s — don't special-case future Popover-in-Dialog usages, they get this for free.

## Today screen — `src/features/today/`

The screen that replaced `App.tsx`'s old placeholder: a time-ordered timeline of today's reminders (done / NOW / up next) plus, on desktop, a Long-tasks rail. Same design system as the rest of the app (grayscale + single pink accent, see `src/index.css` above).

**Day switcher (viewed day).** Today **and** Focus can step through days within **real today ±7** and show that day's view. Vocabulary: the **viewed day** (a.k.a. selected day) is the date being shown; **real today** (`todayLocal()`) is the only day that can start/stop sessions, skip reminders, or delete occurrences; a **past correction day** is an older viewed day where reminders can be marked done/undone but every other action stays hidden; a **future review day** is fully read-only; the **day window** is that ±7 range. `dayAccess.ts` centralizes this policy (`canUpdateReminders` for past+today, `canRunSessions` for today only). The viewed day is held in **`SelectedDayProvider`** (context in `selectedDay.ts`), mounted **above the routes** in `App.tsx` so it survives tabbing between `/today` and `/focus`; it starts at today on cold start and snaps back on a notification tap (`sw.ts` posts `notification-click`; see PWA section). Off-today the reminder list is **flat** (no NOW divider / Earlier / Up-next — "now" isn't inside another day) and the header shows a **relative title** (Yesterday / Tomorrow / weekday) + neutral **`X of Y done`** count. The existing `repo.markReminder`/`clearReminder` date-based write path handles retroactive completion corrections with no schema/data-layer change; `db/dayView.ts`'s `deriveState` resolves past→`missed` / future→`pending` before a correction exists.

- **`useTodayData.ts`** — the one data hook: `useLiveQuery` (from `dexie-react-hooks`, first real usage in the repo) over `src/db/dayView.ts`'s `getDayItems`, plus a minute-tick clock. Takes **`(userId, date)`** — the `date` is the viewed day (from `SelectedDayProvider`); it also computes **`isToday`**, the relative **`title`**, a flat time-ordered **`reminders`** list (the off-today list), and **`totalCount`** (for `X of Y done`). Writes via `repo.ts` (`markReminder`, `startWorkSession`) auto-refresh it — no manual invalidation anywhere in this feature. Only when `isToday` does it split into earlier/up-next time buckets (anchored on `strict_time` for strict, `soft_start` for soft, and **`soft_end` for `random`** — so a not-yet-fired surprise stays in "up next" for its whole window; a `random` row's `timeLabel` is the literal "RANDOM" — its window and exact fire minute both stay hidden) and the header counts — `toGoCount` excludes both `done` and `skipped` ("Missed it") occurrences, so a dismissed item isn't counted as still outstanding (done + toGo need not sum to the total). Real today can also include a long-task session that started on an earlier date and is still `in_progress`; `DayItem.date` remains that start/owner date so actions target the original occurrence. Exports `relativeTitle` (reused by `FocusScreen`, which reads `getDayItems` directly). `streak` is a **hardcoded stub** — real derived-streak calculation isn't built (see `db/CONTEXT.md`).
- **`TodayScreen.tsx`** — top-level responsive shell; literally duplicates the mobile/desktop blocks (`lg:hidden` / `hidden lg:flex`, same precedent as `NewActivityDialog.tsx`) since the two chromes (bottom tab bar + FAB vs. floating island + rail) genuinely differ. Consumes `useSelectedDay()`, feeds `selectedDate` to `useTodayData` and down as `date`, renders `DaySwitcher` in the header, and selects `Timeline`'s flat `offTodayLayout` plus `LongTaskCard`'s genuinely `readOnly` off-today variant. `dayAccess` guards reminder completion writes to past+today and session starts to today; `toggleMissed` remains explicitly today-only. Owns the NOW-marker scroll-into-view (**gated on `isToday`**): a manually computed `scrollTop` on mount, **not** `scrollIntoView` — mixing a scroll container with a flex-1 body has been unreliable for this elsewhere in the codebase too (see `NewActivityDialog.tsx`'s own note on `h-auto` + flex).
- **`Timeline.tsx`** — the one shared timeline body for both breakpoints (rows don't structurally differ, only the surrounding chrome does — same shared-body precedent as `NewActivityFormBody.tsx`). `offTodayLayout` renders the flat `reminders` list with **no NOW divider and no Earlier/Up-next headers**; the separate `canUpdateReminders` access bit lets past rows keep that layout while exposing done/undo. An empty off-today list falls back to `emptyMessage` (a calm line `TodayScreen` derives from past/future).
- **`ReminderRow.tsx`** — a reminder only renders dimmed/checked once `completion.status === "done"`. A reminder whose time has passed with no completion still renders at full opacity with a tappable empty circle, **not** styled as a failure — root `CLAUDE.md` bans punishing "missed" states, so a late reminder stays actionable rather than showing as a failure. The **one** exception is a user-chosen **"Missed it"** dismissal (`completion.status === "skipped"`): dimmed + strikethrough. That's a deliberate act, not the banned system-missed styling. `done` and `missed` are mutually exclusive (one completion; status `done | skipped`). A `random` reminder's `time` cell shows the literal "RANDOM" (built in `useTodayData`) instead of a clock time — its fire minute stays hidden. Off-today the row always drops `TaskActions` (no missed-toggle, delete, kebab, or context menu) and keeps the calm right-aligned state treatment: past rows append only the done/undo circle; future rows have no control. `done` fades (whole-row opacity, plain "Done"); `skipped` keeps the today "Missed it" treatment — faded + struck title — with a "Missed" pill; a **derived** `missed` (past, never marked) stays at **full opacity** as a quiet gray pill (never struck, never red — no-punishing rule); a future `pending` row shows nothing on the right.
- **`TaskActions.tsx`** — the per-occurrence menu (hover-⋮ dropdown on desktop, long-press context menu on mobile — same shared menu). Two actions: **"Missed it" / "Undo"** (reminders only — passed `onToggleMissed`; toggles `markReminder(…, "skipped")` ↔ `clearReminder`, which silences that occurrence's notifications — see root `CLAUDE.md`/`supabase/CONTEXT.md`) and **Delete…** (opens `DeleteChoiceDialog`). Long-task cards don't pass `onToggleMissed`, so they show Delete only.
- **`LongTaskCard.tsx`** — pure router, no layout of its own: `readOnly` (a review-only day) delegates to `ReadOnlyLongTaskCard.tsx`; otherwise an `in_progress` session delegates to `ActiveSessionCard.tsx` (below), and failing that the card is picked by the activity's fixed `default_mode` — `IdleGoalCard.tsx` for goal mode, `IdleZenCard.tsx` for zen mode. Mode is set once at creation and never changes per session, so there's no third branch. Context actions use `item.date`, not the viewed date, because real today may be showing a cross-midnight active session whose stored occurrence still belongs to yesterday. `repo.startWorkSession` guards one `in_progress` session per user/activity; don't add a second "start" entry point that bypasses it.
- **`ReadOnlyLongTaskCard.tsx`** — long-task card for a review-only day: shows what happened **on that day** from the viewed day's own `item.sessions` (per-day, **not** the idle cards' all-time `getCompletedSessions`) — `Xh Ym logged` (+ `· goal met` when a goal-mode session met its target), else a calm `Planned` (future / nothing yet) or `Not logged` (past, none). No Start, no live timer, no kebab. Built to the hi-fi spec (`DESIGN_HANDOFF_day_switcher.md`): idle-card shell (18px radius mobile / 16px in the desktop rail), meta line under the title, a small check glyph on `goal met`, and a compact `45m` / `1h 05m` logged form (local formatter, terser than `lib/utils`' `formatDuration`).
- **`IdleGoalCard.tsx`** — goal-mode idle: a progress bar banked **across every completed session the activity has ever had**, not scoped to today (a goal is worked toward over multiple sittings). Reads via `db/taskHistory.ts`'s `getCompletedSessions` (a `useLiveQuery`, so a `Stop session` elsewhere refreshes it automatically). 0% and "not started" are the same component at the natural low end, not a separate empty state — see the design handoff's own framing of this in `design_handoff_long_task_cards/`.
- **`IdleZenCard.tsx`** — zen-mode idle: a 6-bar greyscale sparkline of the most recent completed sessions (by length, never pink — no goal means no session is "the target") plus a caption rolling up today's total (bolded via `idle-caption-strong`, same emphasis pattern as `IdleGoalCard`'s percentage) and this calendar week's total (since Monday). Boundaries use `db/recurrence.ts` — `todayLocal()` (local calendar day, not a rolling 24h window) and `startOfWeekMonday()` (Mon–Sun calendar week, not a rolling 7-day window) — and totals use `db/sessionSlices.ts`, so a cross-midnight session credits each local day/week for the minutes actually spent there instead of only the `started_at` day. Sparkline, "today", and "this week" are all independently derived from the same `getCompletedSessions` read — the visible bars aren't necessarily all from this week. No sparkline at all (not an empty/flat one) when the activity has zero completed sessions ever; caption becomes "No limit · not started".
- **`db/taskHistory.ts`** — cross-day companion to `dayView.ts`: `getCompletedSessions(activityId)` walks every `day_activity` the activity has ever materialised (`day_activities.activity_id` index) and returns its `completed` `work_sessions`, oldest→newest. This is the one place in the app that reads a `long_task`'s history beyond a single date; both idle cards depend on it.
- **`ActiveSessionCard.tsx`** — the in-session state, structurally independent from the idle cards (header row with icon-ring + live pill, big ticking timer, mode-conditional progress bar vs. breathing baseline, single action button). Reads `mode`/`goal_duration_mins` off the **`WorkSession` row itself** (snapshotted at start), not `activity.default_mode` — matches the goal-snapshot rule so a later activity edit can't retroactively change how a past/running session renders. Owns its own 1s `setInterval` (elapsed derived from `Date.now() - started_at` on each tick, not a naive counter) so the timer ticks independently of the app-wide minute-tick clock in `useTodayData.ts`, which is too coarse for a live `M:SS` display. Single action button — `Finish session` (checkmark icon, pink-tinted pill at rest, identical copy in both modes per the design handoff's correction over an earlier goal/zen-split label) — the design handoff's Pause button was dropped: `CLAUDE.md` settles no pause/resume in v0, and `repo.ts` has no paused state to back it. Mounted from the desktop rail (`TodayScreen.tsx`'s "Long tasks" panel) **and** the mobile Focus tab (`FocusScreen.tsx`) — via `LongTaskCard` in both.
- **`FocusScreen.tsx`** — the **mobile Focus tab** (route `/focus`), the mobile counterpart to Today's desktop Long-tasks rail (which is why it lives here, not a separate `features/focus/`): a single scrolling list of `LongTaskCard`s with the one `in_progress` session pinned to the top, idle tasks below in `position` order. Reads long tasks with a lean `[userId, selectedDate]`-keyed `useLiveQuery` over `getDayItems` (the shared read API) filtered to `long_task` — deliberately **not** `useTodayData`, which also runs a minute-tick clock + reminder derivation Focus doesn't use (reusing it would re-render this list every minute for discarded data); the active-first ordering is memoized on `items`. On real today, this includes cross-midnight active sessions surfaced by `getDayItems`, while the session stays attached to its start date. Consumes the **same `useSelectedDay()`** as Today (shared viewed day across the two screens), renders `DaySwitcher` + the relative day label (off-today it replaces the `Focus` eyebrow), and passes `readOnly={!isToday}` to `LongTaskCard`; `startSession` early-returns off-today. `onStart`/`onStop` go through `repo.ts` (`startWorkSession`/`completeWorkSession`), same as `TodayScreen`. **Mobile-only per the nav divergence** (root `CLAUDE.md`): a small `useIsDesktop()` (the one place we branch on a JS media query — a route redirect has no CSS equivalent, unlike the duplicated-block pattern elsewhere) redirects `/focus` → `/today` at ≥`lg`, since desktop already surfaces long tasks in Today's rail and `DesktopIsland` has no Focus tab to reach the route (only a deep link / stale URL can). Empty state splits on the viewed day: **today** gets a calm non-punishing prompt with a create button (this is Focus, not Stats — no roast); **off-today** gets a quiet single line with **no** CTA (can't act on a review-only day) — "Nothing logged that day." (past) / "Nothing planned yet." (future). Header/list padding + `MobileTabBar` mirror `TodayScreen`'s mobile chrome. Note the active-first sort is view-local (Focus only) — the desktop rail keeps plain `position` order.
- **`NewActivityFlow.tsx`** — the shared "create activity → maybe ask for notifications" flow (owns the reminder-only `shouldOfferAsk()` gate + `NotificationAsk`), driven by a caller-owned `open` boolean. Used by `TodayScreen` (FAB + desktop header button) and `FocusScreen` (empty-state button) so the post-create ask state machine can't drift between screens.
- Sign-out now lives on the **You** screen (`features/you/`), not here. The old `SignOutLink.tsx` (a temporary text link shared by `TodayScreen`/`FocusScreen`) was **removed** when You landed.
- **`selectedDay.ts` / `SelectedDayProvider.tsx`** — the day switcher's shared state (see the Day-switcher paragraph above). `selectedDay.ts` holds the context + `useSelectedDay()` hook + `DAY_WINDOW`; `SelectedDayProvider.tsx` is the provider component (split into two files so the provider's file exports only a component — the repo's `react-refresh/only-export-components` rule, off only for `components/ui/**`). The provider clamps stepping to real today ±`DAY_WINDOW` and listens for the SW's `notification-click` message to snap back to today. Date math reuses `db/recurrence.ts` `addDays` (added for this).
- **`DaySwitcher.tsx`** — the `‹ ›` prev/next controls (disabled at the ±`DAY_WINDOW` bounds) + a `Today` button shown only off-today (there's no calendar jump). Grayscale only — pink stays reserved for CTA/brand/live. One component for both breakpoints (chevrons/pill scale 32→34px at `lg:`); disabled chevrons drop to a low-emphasis fill/border/stroke (not just opacity), hover only lifts the border. Built to the hi-fi spec in `DESIGN_HANDOFF_day_switcher.md`.
- **`iconForActivity.ts`** — the CLAUDE.md-settled "icon derived from type + name, frontend string map, no picker" utility. Keyword-matches `activity.name`, falls back per `activity.type`. Uses `lucide-react` (installed since `components.json` was set up, but unused elsewhere in `src/` until this feature).
- **`MobileTabBar.tsx`/`DesktopIsland.tsx`** — **route-aware** (react-router `useNavigate` + `useLocation`): Today → `/today`, Stats → `/stats`, active state derived from the current path (`/stats/:id` keeps the Stats tab lit). The mobile-only **Focus** tab routes to `/focus` (`FocusScreen`); **You** routes to `/you` (`YouScreen`) — a real tab on mobile (4th) and a segment on desktop (3rd). Desktop (`DesktopIsland`) drops the Focus tab: on desktop, long tasks/focus sessions already have a home in the Long-tasks rail on Today, so a separate Focus destination would be redundant there; mobile has no side rail to put long tasks in, so it keeps its own Focus tab (`FocusScreen` guards the route to mobile). A fake macOS window frame (traffic lights, rounded/bordered outer border) was considered and rejected: this is a browser-tab PWA, not Electron, and the real browser window already supplies window chrome — see the comment in `DesktopIsland.tsx`.

## Stats — `src/features/stats/`

**Built end-to-end** (UI + data layer, live Dexie data). `StatsScreen.tsx` (`/stats`, single-scroll overview) and `StatsDetailScreen.tsx` (`/stats/:activityId`, per-activity detail) are the real screens, built from the design hand-off (produced by a separate Claude *design* session from **`src/features/stats/DESIGN_BRIEF.md`** — the self-contained doc carrying every product/data decision: voice, each stat's definition + source, screen inventory, heatmap spec, palette, wireframes). Both reuse Today's chrome (`MobileTabBar` mobile, `DesktopIsland` desktop; no shared layout route — see App.tsx note) and follow the house **mobile/desktop duplicated-block** rule (`lg:hidden` / `hidden lg:block`), not one responsive tree.

Files:
- `StatsScreen.tsx` — overview: reads `useStatsOverview(userId)`. Aggregate hero (showed-up ÷ planned + focus banked, each with a vs-last-week delta chip) → most-avoided callout → shared visuals (heatmap, focus trend, weekday flake) → per-activity breakdown (tap → detail; archived greyed under a divider). Loading shell keeps the chrome while Dexie resolves; whole-page empty state + per-section guards (hide the heatmap/trend when there's no focus data, the flake when there are no active reminders).
- `StatsDetailScreen.tsx` — reads `useParams().activityId` + `useStatsDetail(userId, activityId)`; back link → `/stats`; loading + "not here anymore" (null) states. The **long-task** variant (summary cards, focus trend, its own scoped heatmap, sessions list with goal-met bars) is the pixel-designed one; the **reminder** variant (adherence cards, adherence trend, completion log) is built from the brief's *described* spec (not pixel-mocked) so every breakdown row's drill-down is functional. Body content branches on activity type (data-driven), inside the duplicated mobile/desktop chrome.
- `Heatmap.tsx` — **hand-rolled ridgeline SVG** (NOT a library; research rationale in DESIGN_BRIEF.md §6). 7 lanes Mon→Sun, gaussian-smoothed Catmull-Rom curves, pink intensity gradient (the one sanctioned heavy-pink use — it's a data signal). Takes a `buckets[7][24]` prop (minutes, local start hour); reused at both scopes. Uses `useId()` for its gradient id.
- `FocusTrend.tsx` — **Recharts v3** `AreaChart`, themed to the tokens (grey `#D6D6D6` line, white area fade, bright last dot, no axes/grid/tooltip, `isAnimationActive={false}`). The repo's **first `recharts` usage** — only this component uses it; the heatmap + flake are hand-rolled. `ResponsiveContainer` measures 0 inside a `display:none` breakpoint block on mount but the *visible* block measures fine and the hidden one re-measures via ResizeObserver when shown, so the duplicated-block pattern is safe.
- `WeekdayFlake.tsx` — hand-rolled 7-bar greyscale strip (missed rate by weekday).
- `parts.tsx` — shared bits: `SectionLabel`, `DeltaChip`/`DeltaMini`, `WeekStrip`, `Sparkline`, `IconTile`, `ActivityRow`/`ActivityList`, `MostAvoided`, `SessionRow`. Activity glyphs come from `features/today/iconForActivity` (the settled "icon from type + name" util), not hardcoded paths.
- `copy.ts` — threshold-driven roast (`fmtMins`, `heroCopy`, `avoidCopy`, empty/no-avoided lines). Attitude lives here, not in JSX. This is the one place root CLAUDE.md's "no punishing missed states" rule is overridden — **scoped to Stats only** (now graduated into CLAUDE.md).
- `types.ts` — `StatsOverview` / `ActivityStatRow` / `StatsDetail` (+ `SessionRecord`/`CompletionRecord`); the shapes the data layer produces and the screens consume.
- `useStatsData.ts` — `useStatsOverview` / `useStatsDetail` `useLiveQuery` hooks over `src/db/stats.ts`. Live: completing a reminder / ending a session refreshes stats with no manual invalidation. `undefined` = loading; detail returns `null` for an unknown id.

**Data layer — `src/db/stats.ts`** (pure Dexie reads, aggregated in memory; see `db/CONTEXT.md`). Loads the user's rows once, indexes occurrence state by `activity_id|date`, then derives everything. Windows: "this week" = the **Mon–Sun calendar week containing today** (partial → elapsed days only, via a `date > today` guard), delta vs the prior calendar week; heatmap all-time. **Archived rule (implemented):** amount stats (focus banked / trend / heatmap) include archived history; rate stats (showed-up ÷ planned / adherence / most-avoided) are active-only; archived rows appear as greyed "history only" (only if they have logged history). Long-task amount/showed-up buckets split completed sessions across local calendar days (cross-midnight sessions credit each day for the minutes actually done there), while session logs/sparklines stay whole-session records. Heatmap buckets spread `work_sessions.started_at` → `started_at + total_secs` across local weekday/hour boundaries (reminder `completed_at` is tap-time, not do-time, so reminders are excluded); timestamps are UTC ISO → `new Date()` renders them device-local, which is what we bucket by. Session/log dates use a fixed English `MMM D` (locale-stable, app is English-only). Week-strip is the current calendar week Mon→Sun and marks *today* (and any future day) as `pending` (not a miss) since it's still actionable; most-avoided has a min-planned floor (2). **Bundle note:** `recharts` pushes the main chunk past Vite's 500 KB warning — code-splitting `/stats` (`React.lazy`) is a reasonable follow-up (lazy chunks still precache for offline).

## You / account — `src/features/you/`

The account screen (`/you`, reachable from the 4th `MobileTabBar` tab and the 3rd `DesktopIsland` segment). Same house chrome rule as the other screens (duplicated mobile/desktop blocks, each renders its own nav — no shared layout route). **Built end-to-end** — the visual layer was produced in a separate Claude *design* session from `DESIGN_BRIEF.md` + the `design_handoff_you` reference package (same convention as Stats; the design files live outside the repo). Four sections: profile (identity), notifications (reallow + live status), app (version + update check), sign-out.

- **`YouScreen.tsx`** — the styled screen. Screens receive only `userId`; email/name come from `useSession()` **directly** (the only screen that re-reads the session rather than taking a prop). Activity count via `useLiveQuery` over Dexie (`db.activities … !archived`). Renders the confirm dialog (below) inline. **Design contracts:** identity *is* the page title (display name as the header; falls back to the email local-part) — **no avatar/initials/photo** (the app will never have one). Pink is CTA-only: the notifications **Enable** and update **Reload** buttons (`Button` default) are the sole pink; **Check for updates** is `Button` outline; sign-out uses a restrained **warm-muted** tint (text `#C97A7A`, border `#3A2A2C`) — never pink, never a loud red. The notification card switches on `notif.status` (`on`/`off`+Enable / `blocked` / `needs-install` / `loading`; hidden entirely when `unsupported`). Section helpers (`NotifSection`/`AppSection`/`SignOutSection`) are parameterized by a `desktop` bool rather than fully duplicated, but the two outer layout blocks are duplicated per the house rule (mobile: fixed header + bottom-anchored sign-out via `mt-auto`; desktop: centered `max-w-[560px]` column). Sign-out confirm dialog appears only when `pendingCount > 0` (unsynced writes) — grayscale Cancel + warm-fill confirm (`#3A2124`/`#542E31`/`#F0DADA`).
- **`useNotificationStatus.ts`** — the **only** live-read of Web Push permission state in the app (elsewhere it's read imperatively at create-reminder time via `shouldOfferAsk`). Returns a status enum (`loading|unsupported|needs-install|blocked|off|on`) derived from `push/platform` + `push/subscribe` (`currentPermission`, `isSubscribed`), re-reading on `focus`/`visibilitychange` (permission can change in browser settings while backgrounded, with no JS event). `enable()` calls `enableNotifications(userId)` from the button gesture. **Reallow-only by design** — there is no off switch, so `disableNotifications` stays uncalled.
- **`useSignOut.ts`** — sign-out that **also clears the local Dexie store** (`db.tables … clear()`), because RLS scopes the cloud mirror but not the local one — a second account on the same device would otherwise see the prior user's rows. Guard: if `syncQueue` has unflushed writes, `pendingCount` is set to open a confirm dialog before discarding; `confirmSignOut`/`cancel` resolve it. Clears **before** `supabase.auth.signOut()` (which unmounts `SignedInApp` via `onAuthStateChange`). Note: cloud-only `push_subscriptions`/`user_settings` are **not** cleared here (see root `CLAUDE.md` open questions).
- **`useAppUpdate.ts`** — read-side companion to `PWABadge` via `useRegisterSW`. Exposes `version` (`__APP_VERSION__`, injected by a `vite.config.ts` `define` from `npm_package_version`), `needRefresh`, and an on-demand `checkForUpdate` (`registration.update()`). **PWABadge still owns the periodic detection + toast** — this hook only captures the registration for a manual check and does not re-wire the interval/listeners (double `register()` is browser-idempotent; duplicate intervals are not). SW is off in dev, so `checkForUpdate` no-ops there; version still shows.

## `src/utils/supabase.ts` — the cloud edge

Six lines: `createClient(VITE_SUPABASE_URL, VITE_SUPABASE_PUBLISHABLE_KEY)`. Needs those two env vars (`.env`, gitignored). Web Push adds a third, `VITE_VAPID_PUBLIC_KEY` (the VAPID public key — safe to ship; the private key lives in Supabase function secrets).

**Behaviour to respect:** this client is the *only* path to the cloud, and per the architecture it must **never be read from in the UI critical path** — UI reads come from Dexie. Two background flows use it, both in `src/sync/` (see next section): **push** drains the queue → Supabase, **pull** reads Supabase → reconciles into Dexie. The pull reads the cloud but hydrates Dexie, not the render path, so the contract holds. Feature code mutates via `src/db/repo.ts` and reads via Dexie, never by calling `supabase` directly.

**One documented exception:** `src/push/` writes `push_subscriptions` and `user_settings` **direct** to Supabase, bypassing Dexie/`syncQueue`. These are cloud-only, server-facing rows (the Edge Function reads them), acquired only while online, and never read from Dexie — so the offline-first write path doesn't apply. This is the *only* place feature code calls `supabase` for writes.

## Sync — `src/sync/`

Two directions, both background, both off the render path (UI always reads Dexie):

- **push / flush** — `syncEngine.ts`: drains `syncQueue` → Supabase. `startSync()` (called in `main.tsx`) runs the first flush and re-flushes on `online`. `update` ops use `.update().eq` (not `upsert`) so a queued edit can't resurrect a row another device deleted.
- **pull / hydrate** — `pull.ts` `pullAll()`: re-reads the user's full row set (RLS-scoped) and reconciles into Dexie — server wins except rows with a pending `syncQueue` entry; local rows absent server-side are deleted (**a delete is terminal**). `useSync(userId)` (mounted in `App`'s signed-in subtree) fires it on session-active + `online` + app-foreground. Full contract in `db/CONTEXT.md`; rationale in ADR 0002.

Glossary: **push/flush** = Dexie→Supabase · **pull/hydrate** = Supabase→Dexie · **sync** = the pair. Note `startSync` is push-only despite the generic name — pull is wired separately through `useSync` because it needs a `userId` and an auth-ready trigger that `main.tsx`'s pre-render `startSync()` can't supply.

## PWA — `vite.config.ts` + `src/sw.ts`

- Strategy `injectManifest` with a custom `src/sw.ts` (chosen because we need custom push + background-sync listeners that `generateSW` can't express).
- `registerType: 'prompt'` — **never silently auto-update the SW.** App is write-heavy (timers, offline writes); a silent reload would kill a session. Prompt the user.
- `injectRegister: false` — registration is wired manually (currently via `PWABadge.tsx`).
- **SW update detection:** `PWABadge.tsx` `registerUpdateChecks` — three triggers: 1h `setInterval` (app left open in foreground all day), `visibilitychange`→visible, and `online`. The last two are the mobile fix: the OS freezes a backgrounded PWA and *resumes* the frozen JS context rather than reloading, so the page-load check never re-runs and `setInterval` is throttled/killed while backgrounded — the reliable moment is return-to-foreground. Throttled to 1/min (`MIN_CHECK_GAP`) so tab-switches don't spam; wired once (`updateChecksWired`) across PWABadge remounts. This is **detection only** — it flips `needRefresh`→prompt toast; the user still clicks Reload (still `registerType: 'prompt'`, never silent).
- **Offline-ready prompt:** enabled, auto-dismiss — offline is a core feature, users need to know it's ready.
- **Icon generation:** `@vite-pwa/assets-generator` `minimal-2023` preset (`pwa-assets.config.ts`) — one source SVG → all iOS/Android/favicon sizes.
- **Edge-to-edge / safe areas:** `index.html` sets `viewport-fit=cover` (+ `apple-mobile-web-app-capable`, `theme-color #0f0f0f`). `viewport-fit=cover` is what makes `env(safe-area-inset-*)` report real values; `theme-color` tints the opaque status bar so, on a dark app, it reads as seamless. **Deliberately NOT using `apple-mobile-web-app-status-bar-style=black-translucent`** — on standalone iOS it shortens the usable viewport at the bottom (top-anchored layouts then show dead space below the tab bar); the opaque `#0f0f0f` bar looks identical here without the quirk. Consequence: any full-bleed or `fixed`/edge element must pad itself with `env(safe-area-inset-*)` (see the mobile header, `MobileTabBar`, and the FAB in `features/today/`) — a hardcoded top/bottom pad will be wrong per-device. Metas are read at launch, so the installed PWA must be re-added to the home screen to pick up changes.
- **SPA deep links (react-router):** client routes are served offline by the SW's `NavigationRoute` (`createHandlerBoundToURL('index.html')`), and on the production server by **`frontend/vercel.json`** (`rewrites`: all → `/index.html`) — so a hard reload on `/stats/:id` returns the app, not a 404. `vercel.json` sits in `frontend/` (assumed Vercel project root, since the app + `package.json` live there).

**`src/sw.ts` current state:** the vite-pwa template (precache + `cleanupOutdatedCaches` + navigation fallback + `SKIP_WAITING`) **plus Web Push handlers**: `push` (shows the notification), `notificationclick` (focuses an open tab or opens `/today`; react-router now owns paths, so the Edge Function may pass a deeper `url` such as `/stats/:id`), and `pushsubscriptionchange` (silently re-subscribes; the app persists the new row on next open via `reconcileSubscription`). `src/sw.ts` is compiled by Vite, so `import.meta.env.VITE_VAPID_PUBLIC_KEY` is available there. The **background-sync handler is still NOT here** — `syncQueue` only drains while the app is alive (see `db/CONTEXT.md`).
